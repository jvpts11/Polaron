# THE STANDARD LIBRARY'S OWN ADVICE, COUNTED. A ratchet: these may go DOWN, never up.
#
# Every number here is a place the library does not follow the language it defines, found by the
# rule beside it. They are not noise and they are not exemptions -- they are the debt the advice
# discovered, written down so that it cannot grow quietly and so that paying it off is visible.
#
# The rule when a count rises: fix the code, or write `[Allow(code:, why:)]` where the shape is
# deliberate. Raising the number is not one of the options.
# The rule when a count falls: lower it here, in the same change. A ratchet that is not tightened
# lets the same debt come back.
#
# A count may also fall because the RULE was wrong, and nine of them were: advice about a `*` that
# came from a type argument rather than from the author's text, about a boolean-and-a-pointer that
# nothing writes through, about a channel whose own class drains it two lines below, about a
# per-element bounds check the compiler already versions the loop to avoid, about `private` on a
# field nothing can write, about a transformer for a class with no subject to apply it, about a
# `move` on an integer, about a scan of a collection the loop itself makes, and about a guard that
# names neither the receiver nor any argument of the call it precedes. A rule that reports a cost
# nobody pays teaches its reader to skip the whole catalogue, so those are defects in the same sense
# as the debt is -- and every one of them gained a sample fixing BOTH answers, so a narrowing cannot
# quietly become a silence with only this number to notice.
#
# `polc --check tests/samples/hello_world.pol --lint-prelude` prints them.
#
# NOT THE WHOLE LIBRARY. A generic is analysed where it is INSTANTIATED, so what this counts is what
# `hello_world.pol` happens to instantiate. Across all 678 samples the union is 1653 against the 1541
# this counted the day it was written, and two files -- `Arena.pol` and `Compare.pol`, which are
# generic end to end -- were not covered by a single line of it.

# WHAT THE TWO BIG NUMBERS ARE, since they are the ones a reader will ask about.
#
# 0B40 is 172 loops whose index the range analysis cannot relate to the array's length, and every
# one of them is a loop `hoistBoundsChecks` refuses -- a call in the body, a nested loop, an index
# the versioner cannot prove affine. The COST is real and measured: the check stays. What is not
# available is the fix the catalogue names, because the bound is genuinely a third quantity: a flat
# matrix indexed `row * n + col`, a stack pointer, a message schedule of eighty words. Paying it off
# means slices or invariants through the numeric and crypto code, which is a piece of work and not
# a pass.
#
# 180 -> 172 on 2026-08-21, and the eight are worth reading because they are the shape the rest is
# not. A THIRD ROUTE opened: the rule now also accepts the method's own `requires`. An invariant can
# only speak about fields, so `sortRange(int[] a, int lo, int hi)` -- every divide-and-conquer
# algorithm in this library -- had no way to state its relation at all, and was being offered three
# fixes of which one breaks the code, one cannot express a sub-range, and one cannot mention a
# parameter. It is sound because a `requires` is emitted as a branch that panics: the body is
# dominated by a block where the condition is known, which is what the range analysis reads.
#
# So the eight paid off are the ones whose relation is a genuine PRECONDITION that was never
# written down -- `Arrays.Ints.sortRange` (the range is inside the array), `Knapsack.maxValue` and
# `IntervalMerge.merge` and `SlidingWindowMax.maxOfEach` (an `n` that says how many without saying
# of what). Each was also a real defect: a caller passing an `n` past the end got a panic from the
# middle of the algorithm instead of a refusal at the door.
#
# 172 -> 159 on 2026-08-26, and these thirteen were never real. The rule asked whether the bound is
# the array's own length and answered "no" for a CONSTANT bound over an array of CONSTANT length --
# `byte[] out = new byte[12](); while (digits < 11)`, which is the commonest shape a small scratch
# buffer has. Both numbers are literals, the relation between them is arithmetic the optimiser does
# before anything else, and there is no check left to prove away. So the rule was at its loudest
# exactly where it was wrong -- and its fix, "write `out.length()`", is strictly weaker than the
# constant AND runs the loop one element further than the author meant.
#
# The remaining 159 are the shape the paragraph above describes: a bound that is genuinely a third
# quantity, in code where the fix is slices or invariants and is a piece of work rather than a pass.
#
# 0B24 is 31 signatures taking three or more of one primitive, where any order compiles. That is a
# real hazard and the fix is a `newtype` or a slice per concept -- an API change across `Time`,
# `Tls` and `Math`, again a piece of work rather than a pass.
#
# 0B21 IS STILL 2 AND ONE OF THEM ALREADY PAID FOR ITSELF. `Router.matches` returns a boolean and
# writes captured `{name}` segments through a `ServerRequest&` -- and it used to capture as it
# scanned, so a pattern that agreed on three segments and failed on the fourth left three parameters
# behind in a request that `dispatch` then handed to the next route. The rule's own sentence about
# the shape is what this was: "reading the out parameter on the false path compiles perfectly and
# gives back whatever was in that storage, which is usually a plausible value and never the right
# one". The defect is fixed and pinned by `router_partial_match.pol`. The count stays because the
# rule's actual fix -- return an `Option` of the bindings -- changes a public signature.
#
# 0B0B IS HELD AT ZERO by two `[Allow]`s and not by a rewrite, which is the other honest answer.
# `String` is immutable, so a loop that concatenates is quadratic in general -- but a TLS record is
# at most 16389 bytes and each `receive` asks for 16384, so the two record readers loop two or three
# times. A builder there would trade a bounded pair of copies for an allocation and a second
# representation of the same bytes, in the one place where the bytes come out as a flat array
# anyway. The reason is written at each of them, which is what the valve is for.
#
# 0B3A IS HELD AT ZERO rather than deleted, so the two it caught cannot come back unnoticed. Both
# were real and neither was the shape the rule described. `BigInteger.addMag` opened with
# `BigInteger a = this` -- a deep copy of the number AND its digit array, on every addition, to get
# a shorter name for a thing it only reads; it is a `BigInteger*` now. `Tls.toBigEndian` copied a
# big integer that had already been copied at the door, because the parameter arrives by value; that
# one really was a transfer written as a copy, and is a `move`.
#
# The first also found a bad `fix:`. The rule said "write `move` instead", and the source there is
# `this` -- a receiver cannot be moved, and would be the wrong thing if it could, because it belongs
# to the caller. The catalogue now names the borrow for that case. A rule whose fix does not compile
# is the same defect as a rule whose fix breaks the code.
